RETRIEVAL ENGINE SCORING
═══════════════════════════════════════════════════════════════════════════════

Each destination field scored by:

  Exact Name Match     (35%) → "customer_id" = "CUSTOMER_ID" → 1.0
  Synonym Match        (25%) → Matches stored business terms → 0.6-1.0
  Metadata Similarity  (25%) → LLM descriptions compared → 0.7-0.95
  Type Compatibility   (10%) → VARCHAR = VARCHAR → 1.0; else 0.2-0.8
  Length Compatibility (5%)  → dest_len ≥ source_len → 1.0; else 0.3-0.7

Formula: score = name×0.35 + synonym×0.25 + metadata×0.25 + type×0.10 + length×0.05

Example:
  Source: customer_id (VARCHAR, 50)
  Dest: KUNNR (CHAR, 10)
  
  name:      0.7 → 0.245
  synonym:   0.9 → 0.225
  metadata:  0.85 → 0.2125
  type:      0.6 → 0.060
  length:    0.2 → 0.010
             Total = 0.7525 (75.25%)

TYPICAL WORKFLOW
═══════════════════════════════════════════════════════════════════════════════

1. CREATE PROJECT
   └─ Specify source ERP system (D365, Oracle, Legacy)
   └─ Specify destination system (SAP)

2. ADD FIELDS
   └─ Upload/add source fields from ERP
   └─ Add destination SAP schema fields
   └─ Add synonyms to destination fields (optional but recommended)

3. RETRIEVE CANDIDATES
   └─ Call /retrieve-candidates endpoint
   └─ Get Top 5 matches without any LLM cost
   └─ See detailed scoring breakdown

4. AI MAPPING
   └─ Call /map-field endpoint
   └─ Retrieval Engine gets Top 5
   └─ LLM receives only Top 5 (not full schema)
   └─ Get back: mapping + confidence score
   └─ Result stored in database

5. HUMAN REVIEW
   └─ Browse all suggested mappings
   └─ Approve/Reject/Edit each one
   └─ Leave review notes for audit trail
   └─ Feedback stored for learning

6. EXPORT
   └─ Export all approved mappings
   └─ Get JSON for integration with target system
   └─ Use for data migration
